# Coop3D System

复杂场景下的车路协同多模态3D感知与通信融合系统。

## 功能要求

### P0：一期必须完成

| 编号 | 功能 | 主要内容 |
|---|---|---|
| FR-01 | 多端数据接入 | 读取车辆端、路侧端图像、点云、时间戳、位姿和标定文件 |
| FR-02 | 时间同步 | 按时间戳匹配多端帧，记录同步偏差，超限帧不得静默融合 |
| FR-03 | 标定校验 | 检查相机内参、外参、LiDAR外参和坐标系方向 |
| FR-04 | 坐标转换 | 将路侧目标、点云或特征转换至当前自车坐标系 |
| FR-05 | 单端3D检测 | 车辆端和路侧端均可独立推理和评估 |
| FR-06 | 协同融合 | 支持中间融合与后期融合，并保留早期融合对照 |
| FR-07 | 目标关联去重 | 匹配多端重复目标并合并置信度，避免重复框 |
| FR-08 | 遮挡收益分析 | 统计单车不可见但协同后可见的目标及召回增益 |
| FR-09 | 通信异常注入 | 可配置延迟、抖动、丢包、乱序、带宽和断连 |
| FR-10 | 位姿误差注入 | 可配置平移、旋转和时间漂移误差 |
| FR-13 | 回放与可视化 | 同步展示多端画面、点云、BEV框、节点状态和指标 |

### P1：核心链路稳定后完成

- FR-11 自适应降权：根据数据新鲜度、检测置信度和几何一致性调整节点权重。
- FR-12 特征压缩：支持通道压缩、稀疏区域或Top-K特征传输，并统计通信量和精度损失。

### P2：后续扩展

- FR-14 协同跟踪：为3D目标分配跨帧ID并输出轨迹。
- 多车辆协同、相机-LiDAR深层融合、端侧部署和真实V2X设备联调。

## 数据

- OPV2V：用于OpenCOOD基线调试、融合模式验证和通信故障实验。
- DAIR-V2X-C：作为一期真实车路协同主数据集。
- 原始数据只读保存，不提交Git；转换数据和缓存必须能够由脚本重建。
- 训练、验证和测试按场景或连续序列划分，避免相邻帧跨集合造成数据泄漏。
- 每次实验记录数据版本、划分、配置、代码提交、模型权重校验值和随机种子。

## 目录结构

```text
coop3d_system/
├── configs/        # 数据、模型、融合、通信和场景配置
├── datasets/       # 数据适配、同步、标定与转换
├── models/         # 单端检测、编码器与融合模型
├── communication/  # 压缩、延迟、丢包和节点状态
├── evaluation/     # 3D AP、遮挡收益、通信和性能评估
├── services/       # 推理接口、错误码、日志和回放
├── ui/             # Web或桌面演示界面
├── tests/          # 单元、集成、回归和验收测试
├── tools/          # 下载、转换、可视化和导出脚本
└── main.py         # 统一命令行入口
```

## 模块职责

- `datasets/`：负责数据读取、检查、同步、标定和坐标转换，不在模型代码中隐藏数据修正。
- `models/`：负责单端检测、特征编码和协同模型，不依赖固定绝对路径。
- `communication/`：负责通信异常、压缩、节点状态和故障日志，不静默丢弃异常节点。
- `evaluation/`：负责检测、遮挡、通信、效率和鲁棒性评估，不使用训练集作为验收结果。
- `services/`：负责推理入口、回放、结构化日志、错误码和接口版本。
- `ui/`：负责回放控制、点云/BEV显示和指标展示，核心算法不得只实现在界面层。
- `tests/`：覆盖数据异常、坐标转换、同步、关联、故障注入、回退和接口测试。
- `tools/`：存放数据检查、转换、可视化、评估和报告导出工具。

## 快速检查

项目骨架建立后，可以运行主入口检查：

```powershell
python main.py
```

预期输出：

```text
Coop3D system initialized.
```

当前`main.py`仅作为项目入口占位。数据读取、模型推理、协同融合和可视化功能完成后，再逐步接入主流程。
